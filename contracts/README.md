# FoMox 代币系统

FoMox是一个创新的代币系统，结合了价格稳定机制、推荐奖励和智能池资金管理。

## 主要功能

1. **基本信息**：
   - 总量：1.1亿枚
   - 初始流动池：1亿枚对1万USDT

2. **交易机制**：
   - 通过PancakeSwap进行买卖交易
   - 自动价格控制机制确保市场稳定
   - 必须通过buyTokens和sellTokens函数进行交易，直接transfer无法与交易对交互

3. **持有机制**：
   - 买入后72小时锁定期，不能卖出
   - 如果继续买入，锁定期重新计时

4. **收益限制**：
   - 最多获取2倍买入金额的收益
   - 超过部分转入项目方地址

5. **双池机制**：
   - Fo池：用户可以存入BNB，自动兑换为USDT并进入排队系统
   - Mo池：来自用户卖出的50%资金，用于自动买入

6. **奖励体系**：
   - 推荐奖励：最多7层推荐关系
   - 直推奖励1%，2-7代每层0.5%
   - Fo池分红：每天晚上00:00按照用户占比分红
   - 用户之间转账自动建立推荐关系

7. **手续费分配**：
   - 买入：3%技术维护，4%推荐奖励
   - 卖出：2%销毁，2%生态地址，2%Fo池分红，1%社区奖励，1%社区长分红

## 社区长机制

FoMox引入了社区长机制，用于建立更加完善的社区结构：

1. **社区长注册**：
   - 由管理员指定特定地址为社区长
   - 社区长可以接收其社区成员的交易分红

2. **社区成员关系**：
   - 当用户A与用户B建立推荐关系时，用户A会继承用户B的社区长
   - 如果用户B本身是社区长，则用户A直接属于该社区长
   - 用户的社区长信息可以由管理员手动调整

3. **分红机制**：
   - 成员每次卖出代币，有1%的USDT自动分配给其所属的社区长
   - 如果用户没有社区长，该分红将转入社区奖励地址

4. **管理功能**：
   - 管理员可以注册或撤销社区长身份
   - 管理员可以手动设置用户所属的社区长
   - 社区长比例可以由管理员调整（最高不超过5%）

5. **查询功能**：
   - 可以查询用户属于哪个社区长
   - 可以查询社区长的所有成员及其数量

## 交易自动路由

FoMox合约实现了交易自动路由功能，使用户体验更加流畅：

1. **自动交易转换**：
   - 当用户尝试直接通过`transfer`与Uniswap交易对交互时，合约会自动将交易重定向到正确的函数
   - 向Uniswap交易对转账会自动调用`sellTokens`函数
   - 从Uniswap交易对接收转账会自动调用`buyTokens`函数

2. **安全保障**：
   - 自动路由功能带有重入保护，确保交易不会被恶意合约利用
   - 交易仍然遵循所有限制规则，包括持有期限制和利润上限

3. **事件通知**：
   - 当检测到通过直接转账进行买卖时，合约会发出特定事件
   - 前端应用可以监听这些事件，提醒用户使用正确的交易方法

4. **例外处理**：
   - 授权地址不受自动路由限制，可以直接进行转账操作
   - 在紧急情况下，可以通过暂停功能禁用自动路由

## 安全特性

1. **防重入攻击**：
   - 所有外部交互函数都使用了重入锁
   - 内部状态在外部调用前先完成更新（遵循CEI模式）
   - 使用双重保护：OpenZeppelin的ReentrancyGuard和自定义重入锁

2. **转账控制**：
   - 使用_beforeTokenTransfer和_afterTokenTransfer钩子函数增强安全性
   - 在代币转移前执行验证，减少潜在攻击面

3. **CEI模式**：
   - 所有函数都遵循"检查-效果-交互"(Check-Effect-Interaction)模式
   - 状态变更在外部调用前完成，避免重入漏洞

## 转账限制

1. **用户交易限制**：
   - 用户必须通过`buyTokens`函数买入代币
   - 用户必须通过`sellTokens`函数卖出代币
   - 不允许直接与交易对地址进行transfer操作

2. **推荐关系建立**：
   - 当用户之间进行转账时，若转入方没有推荐人，会自动将转出方设为其推荐人
   - 最低转账1个代币才会建立推荐关系
   - 通过`transferAndRegisterReferral`可强制建立推荐关系

3. **例外地址**：
   - 合约本身、零地址、销毁地址等系统地址不受转账限制
   - 管理员可以设置地址为转账限制的例外

## 管理员功能

系统提供多种管理员功能，确保项目运行平稳：

1. **系统参数管理**：
   - 灵活调整各项参数：可单独设置每个参数，也可批量更新
   - 费率调整：买入费率、卖出费率、推荐奖励等各项费率可独立设置
   - 时间设置：持有时间、分红周期等均可调整
   - 池子配置：Fo池最小入金、Fo/Mo池比例等可根据需要修改

2. **地址配置**：
   - 单独设置各关键地址：技术维护地址、生态地址、分红地址等
   - 批量更新所有地址
   - 设置/取消例外地址和社区长地址

3. **价格控制**：
   - 更新价格控制梯度
   - 开启/关闭自动买入功能
   - 重置每日价格控制

4. **批量操作**：
   - 批量转USDT功能：向多个地址一次性转账USDT
   - 支持不同地址不同金额的转账方式
   - 支持相同金额向多地址转账的简化方式

5. **紧急管理**：
   - 暂停/恢复系统交易功能
   - 紧急提取误发送到合约的其他代币

## Mo池记录机制

FoMox实现了Mo池有序记录机制，以透明地追踪所有资金流动：

1. **有序存储**：
   - 每笔卖出交易中进入Mo池的资金都有顺序记录
   - 记录包含用户地址、金额和时间戳
   - 通过唯一ID跟踪每笔Mo池存款
   - 同一用户可多次加入队列，每次都会作为独立条目处理

2. **透明查询**：
   - 可查询Mo池中的全部历史记录
   - 可查询特定用户的所有Mo池条目
   - 可查询当前Mo池队列的详细信息
   - 提供多种查询接口便于数据分析

3. **处理状态追踪**：
   - 每条Mo池记录都有处理状态标记
   - 自动追踪已处理的记录数量
   - 按照先入先出(FIFO)顺序处理队列

4. **事件通知**：
   - 每次存入Mo池时发出包含完整信息的事件
   - 前端可监听事件并实时更新队列状态

## F代币推荐关系系统

FoMox引入了专用的F代币系统，用于建立更安全和可控的推荐关系网络：

1. **F代币功能**：
   - F代币是一种可增发的ERC20代币
   - 专门用于建立用户间的推荐关系
   - 与FoMox代币系统协同工作，但分开管理

2. **关系建立机制**：
   - 当用户A向用户B转账恰好1个F代币时，系统自动将A设为B的推荐人
   - 转账会同时触发FoMox合约中的推荐关系注册
   - 安全设计确保只有F代币合约才能调用FoMox的关系注册函数

3. **社区长自动关联**：
   - 在建立推荐关系的同时，系统自动为新用户分配社区长
   - 如果推荐人是社区长，新用户直接成为该社区长的成员
   - 如果推荐人已属于某社区长，新用户继承相同的社区长
   - 关系建立过程不会因社区长分配问题而失败

4. **增发管理**：
   - 合约所有者可以创建新的F代币分配给用户
   - 允许灵活控制推荐关系建立的权限
   - 适用于特殊营销活动和用户激励

5. **升级与安全**：
   - F代币使用UUPS代理模式，支持合约升级
   - 合约间严格权限控制，确保系统安全性
   - 所有关键操作都有事件记录，便于后台监控

## 合约架构

1. **FoMox.sol** - 主合约，实现代币功能和业务逻辑
2. **FoMoxProxy.sol** - 代理合约，用于可升级性
3. **MockUSDT.sol** - 用于测试的模拟USDT合约

## 部署步骤

1. 部署MockUSDT（或使用主网USDT）
2. 部署FoMox实现合约（仅合约代码，不初始化）
3. 部署FoMoxProxy，指向实现合约并传入初始化参数
4. 通过Proxy地址与合约交互

## 初始化参数

部署Proxy时需要提供以下参数：
- USDT合约地址
- PancakeSwap路由器地址
- 技术维护地址
- 生态地址
- Fo池分红地址
- 社区奖励地址
- 项目方地址

## 系统参数

系统有多个可配置参数，包括：
- 价格控制参数（每个流动性区间的涨跌幅限制）
- 费率参数（各类手续费比例）
- 池子参数（Fo池和Mo池的操作规则）
- 推荐奖励参数（各级推荐奖励比例）
- 时间参数（持有锁定时间）

所有参数均可通过管理员功能进行调整.
